## 1. 목표 (Goal)

이용자가 **동학농민혁명(1894) 참여 인물의 직계 후손인지** 판별을 돕는,
에이전트 친화적이고 범용적인 도구를 만든다.

- 입력 성씨/이름/본관/집성촌/파 는 **이용자마다 다르므로 예측 불가** → 모두 자유 입력.
- DB 한계(성씨+이름+지역만 보유, 본관/파 필터 없음)로 인해, 스킬은
  **"후보 명단 추출 + 교차검증 가이드"** 를 정직하게 수행한다 (자동 "후손 확정" 주장 금지).

## 2. 범용성 전략 (Universal Agent Compatibility)

  → Codex / Claude Code / Hermes 등 **어떤 에이전트든 `python donghak.py` 로 실행 가능**.
- `SKILL.md` 는 Claude Code / OpenCode 용 래퍼(지침) 로서만 동작.

- **제로 외부 의존성**: `urllib`, `re`, `html.parser`, `json`, `argparse`, `unittest`(테스트) 만 사용.

## 4. CLI 인터페이스 (`donghak.py`)

| 플래그 | 필수 | 설명 |
|--------|------|------|
| `--surname` | ✅ | 성씨 (예: 백, 이, 김, 변) — URL 인코딩되어 쿼리에 사용 |
| `--bonghan` | ❌ | 본관 (예: 수원백씨) — 레포트 표기/프리셋 매칭용 |
| `--region` | ❌ | 집성촌/연고 지역 키워드 (예: 거창, 경주, 김해) — 필터링 |
| `--branch` | ❌ | 파(派) (예: 정신재공파) — 레포트 표기/필터 |
| `--ancestor` | ❌ | 부모님 확인 조상 실명 (예: 백도홍) — 정확/유사 매칭 |
| `--clan` | ❌ | `clans.json` 프리셋 키 (성씨/본관/지역 기본값 자동채움, 개별 플래그로 오버라이드) |
| `--pages` | ❌ | 최대 처리 페이지 수 (기본: 전체 자동감지 = 무제한) |
| `--json` | ❌ | JSON 형태 출력 |
| `--csv` | ❌ | CSV 형태 출력 (표준 출력 또는 `--out` 파일) |
| `--out` | ❌ | 결과 저장 파일 경로 |
| `--no-cache` | ❌ | `cache/` 재사용 안 함 (항상 재다운로드) |
| `--birth-year` | ❌ | 조회자(후손 추정 본인) 출생년도 — 세대 역산·가능성 순위용 |

| `--gen-interval` | ❌ | 세대 간 연수 (기본 30). 두 생년 모두 있으면 차이로 자동 추정 |

`--clan` 프리셋 예시 (`clans.json`):

- `경주이씨`: surname=이, region=[경주,성주,경상,영남,충남,아산,온양], 항렬=대동항렬(35~70세, 에이전트가 웹 참고로 자가수집 — 종중 족보 확정 권장), 규모=common

## 5. 데이터 흐름 (Data Flow)

### Phase 0 — 규모 탐지 (Scale Probe)
1. `pno=1` GET 으로 전체 건수/페이지 수 파악.
   - 방법 A(GET, urllib): `https://cdpr.go.kr/commit/?menu=231&sf=all&sv=<urlencode(성씨)>&pno=1`
   - 응답 HTML 본문에서 "총 N건" 또는 마지막 `pno` 링크를 파싱해 전체 페이지 수 M 도출.
2. 이용자에게 **"성씨 'X': 총 N건 / M페이지"** 를 먼저 보고 (놓침 방지).

### Phase 1..N — 순차 처리 (Sequential Processing)
3. `pno=1..M` 순차 fetch + parse.
4. 각 페이지 `cache/page_<p>.html` 저장 → 재실행 시 재다운로드 방지(이어하기).
5. 진행로그: `page k/M (n건 추출)` 형태로 실시간 출력.
6. `--pages K` 상한 도달 시에도 **묻히지 않게** 명시:
   `처리 K/M 페이지 완료. 남은 M-K 페이지 있음 — --pages 값을 높여 재실행하세요.`
   (절대 silently truncate 금지)

### Phase 2 — 필터링 & 매칭
7. `--region` 있으면 지역 키워드 정규식으로 레코드 필터.
8. `--branch` 있으면 참여내용/지역 텍스트에 파명 출현 시 가중.
9. `--ancestor` 있으면 이름 정확매칭 + (선택) 유사매칭(편집거리 ≤2).

### Phase 2.5 — clan 항렬표 자가수집 (에이전트 필수)
- 한국 성씨·파는 수천 종류라 중앙 항렬 DB가 없음. `--clan` 제시 시 에이전트가
  **웹/문헌을 직접 검색**해 해당 본관의 항렬 순환표(돌림자)와 파 트리를 `clans.json` 에 기록 후 실행.
- 검색 불가 시 `generations: []` 로 두고 정직 안내(세대 역산 skip). 임의 날조 금지.

### Phase 2.6 — 세대 역산 + 가능성 순위 (--birth-year 있을 때)
- `participant_band(앵커생년)`: 앵커(기본=조회자, `--ancestor-birth-year` 있으면 조상) 출생년도에서
  1894 전후 참여자 출생 추정(~1880)을 뺀 뒤 세대 간격(기본 30, 두 생년 차이로 추정)으로 나눠
  **참여자까지의 세대 수(gen_gap)** 와 항렬 절대세대 밴드(기본 36~44세) 산출.
- `score_candidates`: DB 후보를 **(항렬 세대 부합 + 연고지 + 조상실명 유사도)** 로 점수화.
  - 항렬 점수는 **정보성(+1, "참여자 자격 재확인" — 혈통 근거 아님)** 로 과대평가 방지.
  - 연고지 일치(+3), 실명 유사도(편집거리 기반 최대 +2).
- 친족 관계 라벨: gen_gap 1=아버지, 2=할아버지, 3=증조할아버지, … 자동 표기.

### Phase 3 — 보고서 생성
10. 커버리지 요약: 처리 페이지/전체, 추출 레코드 수.
11. 매칭 후보 목록(이름/한자/지역/참여내용/등록일).
12. `--ancestor` 매칭 결과 + 신뢰도 표기.
13. `--birth-year` 있으면 "세대 역산 + 가능성 순위" 섹션:
    - `이상만(1946) 기준 → 참여자는 약 2대 위(할아버지 세대) 가능성` 형태로 출력.
    - 후보를 점수순 나열 + 이유 표기. **증조할아버지 실명 모를 경우가 많음**을 전제로,
      "위 후보 중 집안(부모님/친척/족보)에서 들은 적 있는 이름이 있는지 가족에게 확인" 안내 포함.
14. 권장 다음단계:

## 6. 파싱 방식 (Parsing)

- HTTP: `urllib.request` + `User-Agent` 헤더. GET 방법 A 사용.
- GET 응답에 인증 관련 `alert('...')` 가 껴들어올 수 있으나 본문 데이터엔 무영향 → 무시.
- 레코드 추출: HTML을 라인/블록 단위로 순회.
  - 이름 정규식: `^[가-힣]+\([가-힣]+\)$` 형태의 "한글명(한자명)" 패턴을 수집.
  - 지역/내용/등록일은 근접 텍스트 블록에서 추출 (`html.parser` 로 구조화 시도, 실패 시 정규식 폴백).
- 방어적 파싱: 사이트 구조 변경 시 추출 0건 → 경고 출력 + `--no-cache` 재시도 안내.

## 7. 에러 처리 (Error Handling)

- 네트워크 실패: 1회 재시도, 실패 시 해당 페이지 건너뛰고 로그, 최종 커버리지에 미반영 페이지 명시.
- 사이트 구조 변경: 파싱 0건 경고 + 수동 점검 안내.
- 페이지 자동감지 실패: `--pages` 명시 유도.
- 비속어/개인정보: DB는 공개 명부이나, 출력 시 민감정보 최소화.

## 11. 한계 & 정직성 (Limitations)

- DB 는 성씨+이름+지역만 → 본관/파는 추론 불가. 동명이인/이본관 혼재 가능.
- "후보 0명" ≠ "참여 안 함". 미신청/이명/실명미상 가능성 열림.
- clan 항렬 데이터는 **에이전트가 웹 참고로 수집**(중앙 DB 없음) — 종중 족보 확정 권장. 임의 날조 금지.
- 항렬 점수는 혈통 근거가 아니며, 가능성 순위는 **상대 지표**. 최종 확정은 가족 인지 확인 → 족보/기념재단 교차검증.
- 스킬은 **판별 보조** 이며, 최종 확인은 가족/종중/기념재단 교차검증 필요.
